01 / Deploy

Atomic switching from Release to production.

Interactively pick a GitHub Release asset in the terminal, or deploy latest with a single command. Supports SHA-256 integrity verification, resumable downloads, and offline local bundles.

View deployment guide ↗
Deploy commands 
# Interactively pick a Release asset
upy release

# Deploy latest official release
upy release latest

# Deploy local offline bundle
upy bundle ./bundle.zip
SPA Static Sites

Atomic symlinks with automatic permission fixes.

Extracted into isolated release folders and switched atomically via the current symlink. Automatically standardizes permissions to 0755/0644 to prevent 403 Forbidden errors in Nginx and Caddy.

Native Systemd Services

Go binaries with atomic units and zero privilege creep.

Runs lightweight Go/Rust binaries under systemd supervision. Guarantees strict service user pre-checks, argument fidelity, port identity probing, and automatic rollback on failure.

Docker / Compose Applications

Graceful handover with automated rollbacks.

Prepares new images and configurations before stopping previous containers to prevent port conflicts. Includes built-in health checks that automatically rollback on startup failure.

01 CI/CD Packaging (from upy-test)
.github/workflows/system.yml
# 1. Compile static Linux binary
- name: Build Go binary
  env:
    CGO_ENABLED: '0'
    GOOS: linux
    GOARCH: amd64
  run: go build -trimpath -ldflags "-s -w" -o bin/web ./cmd/web

# 2. Package manifest + executable
- name: Package bundle
  run: |
    cat << 'EOF' > deploy.yaml
    name: my-api
    version: ${{ github.ref_name }}
    type: system
    target: { os: linux, arch: amd64 }
    system:
      command: ["./bin/web", "--port", "8080"]
    healthcheck:
      url: http://127.0.0.1:8080/health
      timeout: 15s
    EOF
    zip -r bundle-linux-amd64.zip deploy.yaml bin/web

02 / Clean

Scans disk usage with human-readable formatting (MB/GB) and interactively prunes stale bundle caches and obsolete releases. Dual-layer active protection ensures the active current version is never deleted, backed by cross-process locks against concurrent operations.

03 / Backup

Convention backups with lock protection.

Follows convention over configuration, automatically detecting project backup.sh scripts and injecting standardized runtime variables. Guarantees zero dirty snapshots via cross-process exclusive locks, bounded disk footprint through intelligent retention rotation, and instant mobile alerts.

View backup documentation ↗
01 / Convention Script Auto-Discovery backup.sh 
#!/usr/bin/env bash
# Auto-injected: UPY_BACKUP_DIR, UPY_PROJECT_NAME, UPY_TIMESTAMP
mkdir -p "${UPY_BACKUP_DIR}"
BACKUP_FILE="${UPY_BACKUP_DIR}/dump-${UPY_PROJECT_NAME}-${UPY_TIMESTAMP}.sql.gz"

# Execute dump inside container or on native host
docker compose exec -T db mysqldump -u root -p"${DB_PASSWORD}" "${DB_NAME}" | gzip > "${BACKUP_FILE}"
02 / Context & Rotation Optional Config deploy.yaml 
# Optional backup settings
backup:
  script: backup.sh            # Auto-probes backup.sh if omitted
  dir: backups                 # Output directory (<root>/backups)
  retention: 7                 # Keep latest 7 archives, auto-prune older
  timeout: 15m                 # Safety timeout (supports 30s, 5m, 1h)
✓
Cross-Process Mutual Exclusion: Acquires exclusive .deploy.lock (action: 备份中), strictly preventing dirty snapshots from concurrent releases or cleanups.
✓
Automatic Retention Rotation: Automatically scans archive modification times and cleans snapshots past the threshold, keeping server disk usage bounded.
✓
Observability & Mobile Alerts: Pushes instant alerts with elapsed execution times, archive file sizes, and failure reasons to Bark mobile channels.

04 / Notify

Multi-recipient Bark mobile push alerts.

Real-time push notifications for deployments and backups delivered directly to iOS devices via Bark. Zero third-party bots, zero heavy webhooks. Features project-level routing in deploy.yaml, global fallback in ~/.upy/config.yaml, multi-recipient broadcasting, and smart deduplication.

View notification docs ↗
01 / Project Routing deploy.yaml deploy.yaml 
# Project-level multi-recipient notifications
notify:
  bark:
    - "DEVICE_KEY_ALICE"
    - "https://api.day.app/DEVICE_KEY_BOB"
    - name: "DevOps On-Call"
      serverUrl: https://bark.mycorp.internal
      token: "DEVICE_KEY_OPS"
      sound: "chime"
      level: "timeSensitive"
02 / Global Fallback ~/.upy/config.yaml ~/.upy/config.yaml 
# Host-wide fallback notifications (auto-deduplicated)
notify:
  enabled: true
  bark:
    - name: "Lead SRE"
      token: "DEVICE_KEY_SRE"
      sound: "bell"
✓
Multi-Recipient Broadcasting: Notify entire engineering teams, on-call groups, or testing devices in parallel with one event.
✓
Smart Deduplication: Overlapping recipients between project and global configs are merged and dispatched once.
✓
Zero External Daemons: Pure Go HTTP client, zero Redis, zero node processes, and zero webhook gateway services.
Open Source What is Bark?
bark.day.app ↗

Bark is a lightweight, open-source push notification service for iOS. It allows developers to send custom push notifications to Apple devices via simple HTTP GET/POST requests. upy integrates Bark natively to give you instant, zero-middleware deployment and backup observability.
