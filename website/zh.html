核心功能

部署、清理、备份与告警。

01 / 部署

从 Release 到生产，原子秒级切换。

在终端交互选择 GitHub Releases 资产包，或一行命令直接部署最新版本。 支持断点续传与 SHA-256 完整性校验；离线环境下支持本地 bundle 文件。

查看部署指南 ↗
部署命令 
# 交互选择 Release 资产
upy release

# 部署最新正式版
upy release latest

# 部署本地 bundle 文件
upy bundle ./bundle.zip
SPA 静态站点

原子软链切换，自适应权限规整。

解压至独立版本目录，通过 current 软链原子切换。 自动将目录与文件规整为 0755/0644 权限，避免 Nginx / Caddy 出现 403 权限错误。

原生 Systemd 服务

Go 二进制原子纳管，拒绝静默提权。

纳管 Go/Rust 等轻量常驻进程。 严格预检运行账号与权限，启动参数原样保真，端口身份严密防伪，失败秒级自动回滚。

Docker / Compose 容器项目

平滑启停，失败自动回滚。

新版本镜像与配置就绪后再停止旧容器并释放端口，避免端口冲突。 内置健康检查机制，启动异常时自动回滚至上一可用版本。

01 CI/CD 打包流水线 (源自 upy-test)
.github/workflows/system.yml
# 1. 交叉编译 Linux 纯静态二进制
- name: Build Go binary
  env:
    CGO_ENABLED: '0'
    GOOS: linux
    GOARCH: amd64
  run: go build -trimpath -ldflags "-s -w" -o bin/web ./cmd/web

# 2. 打包清单与可执行文件
- name: Package bundle
  run: |
    cat << 'EOF' > deploy.yaml
    name: my-api
    version: ${{ github.ref_name }}
    type: system
    target: { os: linux, arch: amd64 }
    system:
      command: ["./bin/web", "--port", "8080"]
    healthcheck:
      url: http://127.0.0.1:8080/health
      timeout: 15s
    EOF
    zip -r bundle-linux-amd64.zip deploy.yaml bin/web
02 服务器端配置与数据隔离
/opt/my-api/deploy.yaml
name: my-api
release:
  provider: github
  repository: owner/my-api
  asset: bundle-linux-amd64.zip
service:
  user: my-api            # 独立无权限系统账号
  group: my-api
  unit: upy-my-api.service

# 业务持久化数据隔离在 /opt/my-api/shared/data/
# 环境变量与配置位于 /opt/my-api/shared/service.env
✓

✓

✓
有界确定性回滚：新服务失败时，先还原置换前二进制再拉起旧服务，并进行真实 HTTP 存活性验证。
✓

02 / 清理

磁盘空间分析与安全清理。

扫描项目磁盘占用（MB/GB），支持交互式清理历史 bundle 缓存与陈旧版本。 内置双重活跃版本保护，禁止删除 current 正在运行的版本；通过跨进程互斥锁避免并发冲突。

查看清理文档 ↗
清理命令 
# 交互式清理菜单（支持空间分析）
upy clean

# 清理历史 bundle 压缩包缓存
upy clean --bundles

# 仅保留最近 3 个历史版本
upy clean --keep 3
03 / 备份

约定式数据备份，全流程加锁防护。

遵循约定优先原则，自动识别项目中的 backup.sh 脚本并注入环境变量。 执行期间自动施加跨进程排他互斥锁，严防并发写入产生脏数据；支持智能保留轮转策略与 Bark 移动端实时告警。

查阅备份与归档文档 ↗
01 / 约定备份脚本 零配置探测 backup.sh 
#!/usr/bin/env bash
# 环境变量由 upy 自动注入: UPY_BACKUP_DIR, UPY_PROJECT_NAME, UPY_TIMESTAMP
mkdir -p "${UPY_BACKUP_DIR}"
BACKUP_FILE="${UPY_BACKUP_DIR}/dump-${UPY_PROJECT_NAME}-${UPY_TIMESTAMP}.sql.gz"

# 在容器内安全执行 mysqldump 导出并压缩
docker compose exec -T db mysqldump -u root -p"${DB_PASSWORD}" "${DB_NAME}" | gzip > "${BACKUP_FILE}"
02 / 上下文与轮转 可选进阶配置 deploy.yaml 
# 备份功能配置（可选）
backup:
  script: backup.sh            # 自定义脚本路径（缺省自动探测）
  dir: backups                 # 备份产物归档目录（默认 backups/）
  retention: 7                 # 自动轮转保留的最大备份份数（默认 7）
  timeout: 15m                 # 备份最大超时时间（默认 15m，支持 30s, 5m, 1h）
✓
跨进程排他互斥（.deploy.lock）：备份期间获取排他锁（action: 备份中），严格互斥正在进行的部署或磁盘清理，杜绝产生半更新脏数据。
✓
智能自动轮转防爆盘：按修改时间排序自动剔除超出保留阈值的旧备份（默认 7 份），防止历史备份文件无限膨胀撑爆服务器磁盘。
✓
通知告警实时推送：备份完成后自动汇总耗时、产物文件体积，并通过 Bark 等渠道实时推送备份结果与告警。

04 / 通知

多接收人 Bark 移动端即时推送。

部署与备份结果即时推送至 iOS 设备，底层基于 Bark。 无需第三方复杂机器人或臃肿 Webhook。支持在 deploy.yaml 中项目级独立配置、全局配置兜底、团队多人广播与智能自动去重。

查阅 Bark 通知文档 ↗
01 / 写法一与写法二 极简列表与批量指定 deploy.yaml 
# 写法一：极简字符串列表（直接填 Token 或完整 URL）
notify:
  bark:
    - "DEVICE_KEY_ALICE"
    - "DEVICE_KEY_BOB"
    - "https://api.day.app/DEVICE_KEY_CAROL"

# 写法二：统一分组与铃声，指定多个 Token
notify:
  bark:
    serverUrl: https://api.day.app
    group: "payment-api"
    sound: "chime"
    tokens:
      - "DEVICE_KEY_ALICE"
      - "DEVICE_KEY_BOB"
02 / 写法三 按人定制独立属性与自建节点 deploy.yaml / ~/.upy/config.yaml 
# 写法三：详细对象列表（按人定制独立标签、铃声或私有节点）
notify:
  bark:
    - name: "前端负责人"
      token: "DEVICE_KEY_FRONTEND"
      sound: "glass"
    - name: "值班运维"
      serverUrl: https://bark.mycorp.internal
      token: "DEVICE_KEY_OPS"
      sound: "minuet"
      level: "timeSensitive"
✓
项目与全局双层配置：项目专属配置（deploy.yaml）与机器全局兜底（~/.upy/config.yaml）协同运作。
✓
智能合并与自动去重：两处配置重叠的同一个 Token 自动去重仅推送一次，杜绝多条重复报警打扰。
✓
项目独立静音开关：在项目的 deploy.yaml 中声明 notify: { enabled: false } 即可完全静音该项目。
开源利器 什么是 Bark？
bark.day.app ↗

Bark 是一款针对苹果 iOS / iPadOS 设备的轻量、开源即时通知推送服务。只需要发送简单的 HTTP 请求，即可秒级将自定义通知推送至设备。upy 原生内建 Bark，提供零运维、即时响应的发布与备份观测能力。
